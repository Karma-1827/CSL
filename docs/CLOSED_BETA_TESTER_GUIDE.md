# MPTS 封閉測試網站內容設計

本文件是 GitHub Pages 封閉測試網站的首頁內容。測試者不需要閱讀程式碼，也不需要知道系統如何開發；只要選擇自己的角色，依照畫面順序完成全部步驟即可。

測試網站不得顯示帳號密碼、安全問題答案、真實學生名單、VM 資訊或內部弱點。測試帳號請由管理員另外提供。

## 一、選擇測試角色

- [老師測試步驟](CLOSED_BETA_TEACHER_GUIDE.md)
- [學生測試步驟](CLOSED_BETA_STUDENT_GUIDE.md)

每位測試者只需進入自己角色的頁面，但必須完成該頁面的全部適用項目。若同一項功能需要另一個角色接手，先選擇「等待其他角色」，通知對方操作後再回來確認結果。

管理員帳號不列入本次封測問卷。系辦助教請直接參考 [MPTS 管理員操作手冊](ADMIN_OPERATION_MANUAL.md) 完成日常行政工作。

## 二、每一題的測試結果

GitHub Pages 上的每一題都應提供以下選項：

- **尚未測試**：還沒有開始。
- **通過**：操作成功，而且畫面與「應該看到」的內容一致。
- **未通過**：功能錯誤、按鈕無反應、資料不正確或畫面與說明不一致。
- **等待其他角色**：已完成自己的操作，正在等老師、學生或管理員接手。
- **無法測試**：缺少課程、配對、檔案或測試條件，暫時無法進行。
- **不適用**：此帳號本來就沒有這項功能，例如一般師大外籍生沒有「尋找老師」。

選擇「未通過」或「無法測試」時，必須再填寫：

1. 實際看到什麼。
2. 原本預期看到什麼。
3. 使用的裝置與瀏覽器。
4. 發生時間。
5. 截圖；截圖前要遮住密碼、安全問題答案及真實個資。

## 三、測試前準備

1. 使用管理員分配的封測帳號，不要使用真實學生帳號。
2. 測試網址是 [https://mpts.tcsl.ntnu.edu.tw/](https://mpts.tcsl.ntnu.edu.tw/)。
3. 測試資料、私訊、課程名稱、課堂紀錄及佐證連結都以 `【封測】` 開頭。
4. 不要填寫真實電話、真實上課內容或其他不必要的個人資料。
5. 至少使用一次電腦瀏覽器及一次手機瀏覽器。
6. 不要自行刪除測試帳號、課程或配對；需要清除資料時通知管理員。

## 四、步驟卡片的固定格式

每個 `1.1`、`1.2` 等小步驟在網頁上呈現為一張卡片，固定包含：

- **開始前**：完成此題以前需要具備的資料或狀態。
- **怎麼操作**：使用者要點哪裡、填什麼、按哪個按鈕。
- **應該看到**：系統正確時應出現的畫面或結果。
- **截圖位置**：之後插入示範截圖的位置與建議畫面。
- **測試結果**：尚未測試／通過／未通過／等待其他角色／無法測試／不適用。
- **問題說明**：只有未通過或無法測試時才展開。

## 五、需要立即停止並回報的情況

遇到以下任一情況，不要繼續操作，立即截圖並通知管理員：

- 看見不屬於自己的姓名、Email、文件、私訊或課程。
- 老師或學生可以進入管理員頁面。
- 出現 `500`、空白頁或整個網站無法開啟。
- 已填寫的資料突然消失。
- 配對、課程或有效時數明顯算錯。
- 下載的證明姓名、計畫或時數屬於別人。

## 六、回傳方式

測試頁面負責顯示步驟、保存勾選進度及產生結果摘要；Google 表單負責回傳最終結果、問題說明與截圖。若 MPTS 或 GitHub Pages 無法開啟，直接使用管理員提供的備用 Google 表單回報。
